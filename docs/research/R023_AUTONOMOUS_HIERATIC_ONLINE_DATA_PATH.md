## Work executed now

- `tools/hpdb_reference.py` is a **genuinely executable local metadata-only importer**, not a downloader. Reads **public publisher's index.json already downloaded by an operator**, checks 2,065 records in complete mode, validates ID/Gardiner/type/volume/page, exact Tokyo image-reference host and URI, SHA-256s the local actual bytes, records per printed Möller volume/page identity groups and conservatively classifies ambiguous/multi-sign labels.
- The parser **never downloads photo/IIIF pixels, never calls a provider API, never treats printed facsimile pages as original physical manuscript support, and never promotes training/scientific access**. All imported records remain `BLOCKED_REFERENCE_METADATA_ONLY` for corpus admission, irrespective of CC BY 4.0 reference metadata status. This is conservative policy, *not a claim metadata cannot legally be used for other analysis*.
- `tests/research/test_hpdb_reference.py` provides a synthetic-only contract/adversarial suite. No external institutional contact, fees, service subscriptions, proprietary transcription copied or official HieraticBench examples opened. This importer does not require an Egyptologist or new trained model to execute.
- **Subsequent full-source evidence (same W7 research):** Although the Python execution container could not resolve the museum/HPDB source host, the connected **public GitHub original publisher repository** `hp-db/hp-db.github.io` provided its full actual `public/data/index.json` on branch `master` pinned to commit `a8cfcf52632487cf1d61a5793d84c9b2f7192d5a` (file Git blob `6efc36471b47255cfc03f6ba8cf9c887a293bb89`). The complete actual **2,065 rows were parsed and source-field checked**. All 2,065 rows are now normalized in [`data/references/hpdb/`](../../data/references/hpdb/README.md), split by volume (**738, 670, 657**), with **214 printed-page groups**, **1,626 Main, 251 Number, 188 Ligature**, and **1,439 unambiguous single Gardiner references vs 626 compound/uncertain**. This is a **real published, CC BY 4.0 metadata reference release**, not merely a synthetic parser. However **no original Tokyo IIIF pixels, human expert reading/line alignment, publisher-signed raw-content SHA-256, model inference or newly validated scientific performance** was obtained. The publisher Git commit/blob preserves provenance; exact full bytes were read via connector, not mirrored raw to Git. To reproduce independently, download the upstream `index.json` and use `python -m tools.hpdb_reference --index path/to/index.json --output path/to/new-reference-output.json` (choose a new output destination).

## Autonomous scientific roadmap: do not confuse reference levels

### A. Research-grade source universe (no third-party hire needed)
Build three independently tagged tracks, never collapse them:
1. **Metadata/reference track:** HPDB CC BY dataset + source support aliases, Möller sign mappings, exact script/period/genre tags. May be used to develop sign dictionaries, metadata search, rendering and source matching with required attribution. **No actual scanned source pixels in this track.**
2. **Public museum-pixel track:** verified individual **CC0 original museum photos** (Met or Museo Egizio) stored in an ignored private data directory with image rights, file SHA, side/fragment/source identifiers. Unsupervised line localization, image segmentation, deskew, historical handwriting enhancement/region proposals are measurable engineering tasks with real pixels **without any transcription label**. **Unsupervised visual diagnostics are not measured script-reading proficiency**.
3. **Scholarly edition reference track:** specific published line readings and translations on UCL/TPOP/Rivista/AHGP sites; first **locate exact corresponding witness/side/line and image**, inspect per-piece reuse, version and edition rights, and attach provenance citations. For training, only ingest author/editor text with documented permitted rights. Otherwise use a research-only bibliography, not a copied training corpus.

### B. Silver-reference pilot, not independent gold
Where original image and editorial text rights are actually satisfied, use existing *published expert editions* as **literature-derived silver labels**: encode edition, witness, line index, alternative restoration, disputed signs, translation differences, annotator identity and provenance. A deterministic aligner and **two independent AI passes** can generate candidate image-to-line locations/sign readings and disagreements; preserve uncertainty. These passes do **not** replace independent Egyptologist validation and **must not be promoted to blind test gold, expert agreement or validated VLM capability**.

### C. Build and test actual capabilities before a single full-line benchmark
Sequential, minimal set with hard experimental boundaries:
1. Verify **one actual original CC0 Hieratic image**, exact bytes/hash, decoder/orientation/scale and object grouping; then extract line/region crops, report segmentation/ROI quality for human visual inspection **without pretending OCR accuracy**.
2. Explore **Möller-linked sign recognition in held-out source-page groups** using only independently licensed *underlying* facsimile imagery. Source-support/printed volume information controls leakage; if scan permission remains unresolved, stay with metadata/references.
3. Bring in DDD **only under isolated NC research assumptions**, with 50-document source-group partitions, no commercial distribution and no automatic project progress claims. Test simple segment detection/visual morphology where allowed.
4. Attempt **one labelled original image↔licensed published edition line** as `silver_literature_reference`, never canonical gold. Use blinded two-pass image-conditioned readings, preserve raw observations and quantify model agreement against published line while explicitly acknowledging that published/seen source might have been memorized.
5. Progress to actual held-out high-confidence expert-backed tests *when such evidence becomes available*; expert engagement is **deferred, not abandoned as scientific validation**.

### D. Where online data remain limited, do not stall
We can still deliver working preprocessing, sign-index conversion, baselines on permitted real images, credible provenance, retrieval tools, transparent uncertainty layers, secure custody and demo-grade visual correspondence. The remaining restriction should be stated precisely (e.g., missing rights to UCL photo vs genuinely unavailable published text vs model weights/hardware), never as generic "we need an Egyptologist before proceeding."

## Guardrails preserved
- **Official HieraticBench 266 public items are evaluation-only; two sealed items excluded.** No benchmark photos, gold, facsimiles, aliases or linguistic material leak into training/dev/few-shot.
- **No author, scribe or corpus-level independence is established by HPDB Gardiner labels or printed-page disjointness alone.** Original manuscript sources and publication variants require identification.
- **Publicly free to view** is not itself a data-training licence. CC0 image, CC BY metadata, CC BY museum journal photo, NC editorial text and GPL code are *different asset categories*. Retain attribution/terms by component.
- **DATA-008 protected production gate and VLM scientific certification stay disabled.** A functional metadata/reference asset importer can be accepted as engineering without capability points. Do not change `PROJECT_STATE.yaml` progress, weights or task validation based on this research alone.
