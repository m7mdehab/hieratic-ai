# Image-to-text alignment

`schemas/alignment_manifest.schema.json` defines alignments between acquisition object identity, DATA-004 page/region IDs, and line/sign/token targets. The CLI validates both the DATA-002 acquisition schema and the DATA-004 annotation schema/invariants before checking cross-file identity, region/page membership, and page/line reading order. Empty target sets require an explicit omission/gap/damage/unresolved relation; unmatched text and image regions are never silently discarded. Coordinates remain owned by DATA-004 annotation geometry and its declared coordinate system; alignment stores stable region IDs rather than copying or transforming coordinates.

Relations include one-to-one, one-to-many, many-to-one, ligature, omission, gap, damage, editorial restoration and unresolved. Competing hypotheses, confidence, reviewer state and provenance are retained. Dependencies are cycle-checked, and contradictory resolved mappings for one image region fail. Gold eligibility is derived, never trusted from user input: only resolved, reviewed/adjudicated, reviewer-attributed, confidence-bearing alignments with explicit targets, provenance and no competing hypotheses can be eligible; damage, omissions, gaps, restorations, unresolved/disputed targets and benchmark material remain excluded.

Run `python -m tools.alignment validate MANIFEST.yaml --acquisition ACQUISITION.yaml --annotation ANNOTATION.yaml [--output FILE]`. The checked-in example uses the DATA-002 and DATA-004 contracts with synthetic identifiers and includes no image or transcription answer. Synthetic fixtures are exempt only from real acquisition-completion requirements; they do not imply that conditional rights are cleared. Real assets still require DATA-002's independent acquisition admission checks. This task has no dependency on DATA-003 preprocessing.
